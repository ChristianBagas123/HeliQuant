**Agent token 8.** This desk is the path by which a **validated trading edge** — fading crowded perp
open-interest — could reach the PM. It only fires when *both* a registry-validated edge **and** a live signal
align. On NEAR the registry is empty, so today it supplies context only (see the caveats below).

## What it reads

`firm/organization.py · tool_oi_contrarian()`:

- **Validated-edge registry** — `data/validated_edges.json`, produced by a **cost-aware OOS backtest**
  (`scripts/59` through `firm/edge_lab.py`, or `scripts/39` for the OI backtest). Holds `p_win`, `payoff_b`, `sample_n`, `oos_roi_pct` per asset that survived.
- **Live OI-contrarian signal** — perp **OI 24h-change quintiles**: top quintile → **SHORT**, bottom
  quintile → **LONG** (fade the crowd).


## Honest caveats

The method is only worth acting on when an asset has **earned** it. On NEAR it has not: Bitget publishes
open interest only as a live snapshot, so the OI column is empty in the history and the hypothesis cannot
be validated (Finding #6). Crucially, **the registry is allowed to be empty** — and it is. This desk is
**context only** for NEAR, and the firm abstains. If an asset's edge ever clears the gate, it is sized with
fractional-Kelly and hard risk caps, never bet as a sure thing, and it stays *earned* on every re-test.
